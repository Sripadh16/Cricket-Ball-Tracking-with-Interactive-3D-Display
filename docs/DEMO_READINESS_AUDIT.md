# Crease / Lab demo readiness audit

Reviewed against upstream main at `bf3142a`. The audit followed the entry screen, simulation, recording and upload, processing, source playback, reconstruction, review evidence, authentication, and local delivery paths. Verification focuses on the demo flows and their data boundaries.

| Area | Finding | Change |
| --- | --- | --- |
| Dashboard | Repeated upload and simulation actions competed for attention, and guest creation blocked the entire entry screen. | Give the simulation the primary action, put upload and recording in one panel, and connect the delivery library independently. |
| Simulation | Standard deliveries required the server. A shared 2,100 RPM setting overrode presets and changed the default leg-break decision. | Bundle the four standard trajectories generated by the Python engine. Preserve the spin built into each delivery and keep custom calculations on the API. |
| Replay | Measurements came before the verdict, the scene title exposed the result early, and event markers kept moving after playback stopped. | Put the verdict first, reveal it at the corresponding event, and drive the scene markers from replay time. Label the playback action and add an oblique overview for desktop simulations. |
| Upload | The upload handler awaited tracking even when the caller requested asynchronous processing. | Return the processing record as soon as the file is stored and run tracking in the existing bounded executor. Show progress alongside the original clip. |
| Review evidence | Uploads used a heuristic fit that could infer an out or not-out from incomplete footage. | Use the camera and ballistic solver for uploads and reprocessing. Keep measured 2D points when geometry fails, require tracked flight near the striker before showing a wicket projection, and withhold automated LBW verdicts on footage because the tracker cannot verify pad contact. |
| Access control | Guest accounts shared an identity. The stream granted special access to the shared guest identity, and the progress endpoint did not authenticate its caller. | Issue distinct guest accounts, retire the shared password login, and apply the same ownership check to streams, trajectories, and processing progress. |

## Remaining priorities

1. **Public deployment.** Require a deployment-specific JWT secret. Move native media playback to short-lived, clip-scoped credentials and review request logging and caching before exposing the API publicly. Previously issued tokens for the retired shared guest account can still reach that account's existing library until expiry or server-side revocation. The existing recordings remain in place. The Compose frontend sets `REACT_APP_API_URL` while the client reads `REACT_APP_API_BASE_URL`. Verify the built client's API URL and reverse-proxy routing before deploying.
2. **Real footage accuracy.** Run the detector and camera fit against labeled cricket clips from the intended camera angle. Report track coverage, false positives, reconstruction success, and stump-plane error by angle. Synthetic footage verifies pipeline behavior.
3. **Job recovery.** Tracking jobs and progress still live in the API process. Add durable job state and restart recovery if the deployment needs multiple API workers or must survive restarts. Add an account recovery or promotion flow if guests need durable access after their token expires.
4. **Maintainability.** Extract the replay decision model and shared evidence rules from the large React review component once a second consumer needs them. Keep the camera fit and 2D fallback covered independently before splitting the tracker.
5. **Browser coverage.** Rehearse the saved clip and check camera permissions on the presentation machine. The local API passed with a real 852 × 480 MP4 and returned a 2D track with no verdict. Use labeled footage with clear landmarks to validate the real-camera wicket projection before relying on it in the demo.

When the simulator changes, refresh the offline data from the repository root with `python scripts/generate_standard_deliveries.py`. Use the [demo script](DEMO_SCRIPT.md) for the presentation order.
